# Syntaxe — classe et `mappers`

Référence de [`SKILL.md`](../../SKILL.md). Entête de fichier et types de documents : [`fichier.md`](fichier.md) ; propriétés d'une classe : [`proprietes.md`](proprietes.md).

## Classe

```
tags, trigram, name, pluralName, sqlName, extends, inheritanceStrategy,
label, reference, defaultProperty, orderProperty, flagProperty, localeProperty,
discriminatorProperty, discriminatorValue, translation, preservePropertyCasing,
propertySourceOrder, type, readonly, comment, enum, implements, decorators,
annotations, excludedAnnotations, propertyAnnotations, properties, unique,
indexes, values, customProperties, mappers
```

Sens des clés principales (persistée ou DTO, effets de `reference: true`, `readonly: true` sur un DTO, liste à `values:` dont la PK est auto-générée : [`regles/classes.md`](../regles/classes.md)) :

- `reference: true` → liste de référence ; `enum: class` génère les constantes ; `readonly: true` la fige.
- `enum` — deux modes, conséquences différentes en base :
  - `class` (**défaut** d'une classe à `values:` dont la PK n'est pas auto-générée, ex. `StatutCommande`) : table, valeurs insérées, FK depuis les associations ; la PK est typée par une enum générée.
  - PK auto-générée (domaine `autoGeneratedValue: true`) avec `values:` : pas d'enum de codes ([`regles/classes.md`](../regles/classes.md)).
  - `true` : vraie enum du langage cible (membres = valeurs de la PK, ex. `PARTICULIER`), et `readonly` forcé. **Ni table, ni entité, ni FK** ; type de colonne et représentation front selon le générateur ([`generateurs.md`](../generateurs.md)).
  - `false` : désactive l'enum déduite.
- Propriétés déduites automatiquement si la classe a une propriété du nom indiqué : `defaultProperty` (`Label`, `Libelle`), `orderProperty` (`Order`, `Ordre`), `flagProperty` (`Flag`), `localeProperty` (`Locale`).
- `type: abstract` pour une classe mère non instanciable.
- **Héritage** : `extends` sur l'enfant + `inheritanceStrategy` sur le parent.
  - `joined-tables` — **le défaut** : une table par classe, FK vers le parent.
  - `single-table` : une seule table, colonne discriminante (propriété `Discriminator` ajoutée par défaut, colonne `{TRIGRAMME}_DISCRIMINATOR`, ou la propriété nommée par `discriminatorProperty`), chaque sous-classe portant son `discriminatorValue`.
  - `distinct-tables` : une table complète par classe concrète, colonnes du parent dupliquées.
  - ⚠️ `discriminatorProperty` doit désigner une propriété **réellement déclarée** sur la classe, sinon `TMD0004`.
  - Le discriminant peut être une **association** : `discriminatorProperty` prend le **nom généré** de la propriété ([`regles/associations-alias.md`](../regles/associations-alias.md) § Associations). Vers une classe `enum: true`, c'est le nom de la classe associée (`TypeClient`), pas `TypeClientCode` (→ `TMD0004`) ; vers une classe ordinaire sans `useClass`, c'est au contraire `TypeClientCode`. Les `discriminatorValue` restent les codes (`PARTICULIER`) ; le mapping généré dépend de la stack.

## `mappers`

Génèrent les conversions entité ↔ DTO. `from:` produit une méthode statique de création de la classe courante (un ou plusieurs `params` : `{ class, name, required, comment, mappings }` ou `{ property, target }`), `to:` produit une méthode de conversion (`{ class, name, comment, mappings }`) ; noms par langage : [`generateurs.md`](../generateurs.md). `mappings:` force (`ProprieteCourante: ProprieteCible`) ou désactive (`MaPropriete: false`) une correspondance. Règles de correspondance, listes, converters : [`regles/mappers.md`](../regles/mappers.md).
